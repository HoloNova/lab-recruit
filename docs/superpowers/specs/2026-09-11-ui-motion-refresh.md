# UI / 动效改版计划 v2 —— 移动优先

日期：2026-09-11
类型：Design + Frontend（改造，非新建）
范围：`public/index.html` · `public/style.css` · `public/app.js`
基线：`npm test` **92/92 通过**，`git` 工作区仅一份未提交文档

> **v2 说明**：v1 提的「实验台 / 电路板」方向**已废弃**。理由见 §0。
> 本版以**移动端**为第一设计目标，所有尺寸与断点先在 390×844 上定，再向上放大。

---

## 0. 为什么推翻 v1，以及改了什么

| v1 | 问题 |
|---|---|
| 「电路板 / 布线脊 / 焊盘」 | **意向错了**。电路板把四个方向压成了「硬件」一个方向——实验室有软件、硬件、算法、人工智能四块，用一个硬件器物做整页的隐喻，等于让另外三个方向做客 |
| `text=` 写死 37 个中文字 | **前提错了**。文案是自动生成的、会变的，把字形冻结在某一段文案上，改一个字就掉字形 |
| 滚动驱动的全站 spine | **成本结构错了**。常驻 rAF 在手机上就是耗电与掉帧，而这页 93% 的访问是手机 |

v2 的三条替换：

1. 意向换成 **方格纸 + 一条被绘制的信号线**（§3）——方格纸是四个方向**共同**的草稿纸，不是任何单个方向的器物；
2. 中文字体只冻结**实验室名这一个词标**（2.7 KB），其余中文全部走系统字体（§4）；
3. 动效预算改成 **零常驻 rAF**（§6）——没有一处持续跑动画循环。

## 1. 移动端实测诊断（本版的核心依据）

用 Playwright 在 320 / 375 / 390 / 430 / 844×390 五个视口实测，`isMobile:true, hasTouch:true`。

### 1.1 五个手机宽度共用同一套字号 —— 移动端没有排版，只有常量

实测 `clamp()` 在手机区间的**实际取值**：

| 元素 | CSS | 320px | 375px | 390px | 430px | 844px |
|---|---|---|---|---|---|---|
| `.display` 主标题 | `clamp(3rem,9vw,7.4rem)` | 48 | 48 | 48 | **48** | 75.96 |
| `.tagline` 副标 | `clamp(.95rem,1.8vw,1.25rem)` | 15.2 | 15.2 | 15.2 | **15.2** | 15.2 |
| `.sec-title` 区块标题 | `clamp(1.8rem,4vw,2.8rem)` | 28.8 | 28.8 | 28.8 | **28.8** | 33.76 |
| `.dir-row .cn` 方向名 | `clamp(1.7rem,4.5vw,3rem)` | 27.2 | 27.2 | 27.2 | **27.2** | 37.98 |
| `.tl-title` 步骤标题 | `clamp(1.15rem,2.2vw,1.5rem)` | 18.4 | 18.4 | 18.4 | **18.4** | 18.57 |

**五个 clamp 的下界在 320–430 全区间都生效**——因为要越过下界分别需要视口 ≥533 / 844 / 720 / 604 / 836px。
320px 的 SE1 和 430px 的 Pro Max 屏幕宽度差 **34%**，字号**一个像素都没变**。

> 也就是说：这套「流式排版」在最需要它的地方（手机）是**常数**，在不需要它的地方（桌面）才开始动。
> 而且反过来了——主标题在 320px 上 48px 占满宽度，在 430px 上却显得小。

### 1.2 小字太小，且 iOS 会在每次点击输入框时缩放页面

| 元素 | 实测字号 | 问题 |
|---|---|---|
| `.field label` 表单标签 | **11px** | 11px 中文 + `letter-spacing: 1.98px`，手机上不可读 |
| `.sec-label` 区块小标签 | 12px | 勉强 |
| 输入框 / 下拉框 | **15px** | ❌ **iOS Safari 在 `<input>` 字号 <16px 时聚焦会自动放大页面**，本页 7 个输入框全部命中 |
| 正文（`.tl-desc` / `.notice-body`） | 15.2 / 15.04px | 偏小 |

> `viewport` 未设 `maximum-scale`，共享的是用户可自由缩放——这一点是对的，**不要动**。
> iOS 的输入框缩放是**平台既有行为**（Chromium 无此行为，故此处无法实测，按代码推断）：
> 唯一解是把输入框字号提到 ≥16px。

### 1.3 触控目标：27 个里 18 个低于 44px，其中 5 个在拇指最够不着的位置

```
under44 = 18 / 27      under24 = 8 / 27
顶部 25% 区域（单手最难够到）: 5 个  ← 全部是导航
底部 40% 区域（拇指舒适区）  : 22 个
```

实测清单（节选）：

| 元素 | 高度 | 屏内位置 |
|---|---|---|
| `.nav-brand` | 20px | 第 2–3% 行 |
| `.nav-links a` ×4（方向/时间线/报名/加群） | **18px** | 第 2–4% 行 |
| `.link-btn`（换一张 / 退出修改） | 23px | — |
| 表单 `input` ×5 | 39px | — |
| 表单 `select` ×2 | 41px | — |

底部 40% 的舒适区里有 22 个目标，但**其中没有一个是可以长期停留的动作**——页面上唯一的转化动作（提交报名）埋在表单末尾。
换句话说：**拇指区有东西，但都不是要按的东西。**

### 1.4 八个屏里有两个几乎是空的

实测（390×844）：

| 区块 | 区块高度 | 实际内容高度 | 空置 |
|---|---|---|---|
| `#notices` 公告 | 844px | **241px** | **603px 空白 = 71%** |
| `#links` 友链 | 844px | 2 张卡片 | 大面积空置 |

数据库当前实际内容：**公告 1 条、友链 2 条**。
`min-height: 100vh` 强制每块占满一屏，于是「1 条公告」占了整整一个 844px 的屏。

### 1.5 横屏彻底失控

844×390 实测：

```
总长 12.2 屏（比竖屏的 8.2 屏更长）
#join .join-info p 宽度 = 150px  → 约 10 字/行  ❌
.dir-row .desc  display: block   → 手机上隐藏的内容在横屏又冒出来（方向切换时内容出现/消失）
#hero 488px / #directions 710px / #notices 403px  → 全部超过 390px 视口高
```

横屏下 `min-height: 100vh`（=390px）+ 内容溢出，导致每一屏都被撑破，`scroll-snap-align: start` 落点全乱。

### 1.6 其他实测/代码层问题

| 项 | 实测 / 代码 | 影响 |
|---|---|---|
| 页面左右内边距 | `6vw` → 19.2 / 22.5 / 23.4 / 25.8px | 四台设备四个值，无理由 |
| `-webkit-text-size-adjust` | `auto` | iOS 横屏会自动放大/缩小文字，与设计不一致 |
| `viewport` meta | 无 `viewport-fit=cover` | 无法用 `env(safe-area-inset-*)`；刘海机不铺满 |
| `min-height: 100vh` | `.screen` | iOS 的 `100vh` 含地址栏，底部内容被浏览器 chrome 遮住 |
| `resize` 监听 | `resize(); seed();` | **地址栏收起/展开都会触发 resize → 重新生成全部 150 个粒子**（手机上一个真实卡顿源） |
| 背景 canvas | 390×844@3x → 780×1688 背衬，每帧 53 个 `createRadialGradient` | 常驻全屏 rAF |
| `scroll-snap-type` | `y mandatory` + 滚动条 `display:none` | 8.2 屏逐屏硬跳 + 零位置反馈 |
| `.dir-row .desc` | `display:none`（≤760px） | 手机是主要设备，却把方向描述删了 |
| 对比度 | 占位符 `#4a4a4a` on `#000` = **2.37:1**；`.opt` ≈ **2.45:1** | ❌ 均远低于 4.5:1 |
| `line-height` | `.tl-desc` 26.6/15.2 = **1.75**，`.notice-body` = **1.8** | ✅ 这一项本来就是对的，**不动** |

## 3. 设计方向：方格纸 / PLOTTED

### 3.1 概念

页面是一张**方格坐标纸**，上面有一条**被绘制的信号线**。

- **方格纸**是软件、硬件、算法、人工智能**共同**的草稿纸——画流程、画电路、画曲线、画网络。它不属于任何一个方向，所以它不会像电路板那样偏心。
- **信号**是四个方向共同的处理对象：软件处理逻辑信号，硬件处理电信号，算法处理数学信号，AI 处理被学习的信号。而一个安全实验室的全部工作，可以概括成一句话——**判断一段信号是真的，还是伪造的**。
- 所以**选方向 = 选你要在哪一层上处理信号**。这正是这页要帮同学做的事。

### 3.2 为什么这次不是「又一个隐喻」

方格纸在这里是**功能面，不是贴图**：

- 它是那条信号线的**绘图区**（坐标网格）；
- 它的网格线同时充当版式的**对齐基准**，所有区块规则线与网格同拍；
- 它零图片、零请求（`repeating-linear-gradient`），打印、缩放、深色模式全部自适应。

**一条硬规则**：网格只作为背景与对齐基准存在，**绝不**往上叠任何装饰性图形。

### 3.3 颜色令牌（对比度全部实算）

#### 浅色（默认）

```
--paper      #f7f7f4   坐标纸 — 中性偏冷，刻意避开奶油 #F4F1EA 与 #F4F1EA 同族
--ink        #16181a   正文 / 标题              16.59:1  AAA
--ink-2      #5c6165   次级 / 占位符 / 标签      5.84:1  AA
--signal     #17469e   唯一强调色（文字/链接/按钮） 8.13:1  AA
--signal-line#1b4fd8   仅用于描边，永不用于文字
--rule       #d9d9d1   分割线 / 字段下划线        结构线，豁免
--grid       #e7e7e0   坐标网格                   结构线，豁免
--fault      #b3261e   只表示错误                6.09:1  AA
--fault-fill #b3261e   错误态填充，白字在其上     6.54:1  AA
```

#### 深色（`prefers-color-scheme: dark`，手机上系统深色模式很常见）

```
--paper      #14161a      --ink     #eef1f4  15.98:1 AAA
--ink-2      #98a0a8   6.84:1 AA   --signal  #6f9dff  6.85:1 AA
--rule       #2a2e34      --grid    #22262b
--signal-line#8ab0ff   8.40:1（描边）      --fault   #ff8073  7.41:1 AA
```

> `--signal-line` 在纸面上的描边对比度实测 **6.20:1**，深色模式 **8.40:1**——都高于 3:1 的图形元素要求，
> 所以那条线在两种底色下都看得清，不靠加粗来保可见性。

**两条硬规则**（不让配色退化成「任意浅底 + 任意强调色」）：

1. `--signal` 只表示**「这条线正在被绘制 / 这台设备是活的」**——即：信号线本体、当前选中项、焦点环、链接。
   不做标题色，不做装饰块，不做渐变。
2. `--signal-line` **只做描边**。因为它对纸面只有 4.6:1 级别的边距，做小字不安全。

> 为什么是蓝不是红：红在暖色纸面上直接落进「赤陶/奶油」那一族的观感，而蓝墨 + 冷纸 + 方格是**图纸**的语言，不是「AI 生成的落地页」的语言。同时蓝在深色模式下也更好收。

### 3.4 字体（中文只冻结一个词标）

因为文案是自动生成的，**任何按文案内容冻结的中文字体子集都是脆的**。所以：

| 角色 | 字体 | 体积 | 规则 |
|---|---|---|---|
| **词标** | Noto Serif SC 700，`text=` 只含「网络攻防与信息安全」9 字 | **2.7 KB** | **只用于实验室名**，当作 logo，不是文案。实验室名不会变，所以不会掉字形 |
| **中文正文 / 标题 / 界面** | 系统栈（下方） | **0 KB** | 所有会变的中文都走这里 |
| **拉丁 / 数字 / 标签** | Martian Mono 变量 `wght 400..700` | 23 KB | 只用于**纯拉丁/数字**串；混排中文的标签用系统栈 |

```css
--font-wordmark: "Noto Serif SC", "Songti SC", "Source Han Serif SC", "Noto Serif CJK SC", serif;
--font-sans: system-ui, -apple-system, "PingFang SC", "HarmonyOS Sans SC", "MiSans",
             "Source Han Sans SC", "Noto Sans CJK SC", "Microsoft YaHei", sans-serif;
--font-mono: "Martian Mono", ui-monospace, "SFMono-Regular", Consolas, monospace;
```

**总字体下载：2.7 + 23 = 约 26 KB**（当前线上 latin 首次加载实测 **130 KB / 7 文件**）→ **−104 KB**。

**为什么中文刻意不下载**：① 文案会变，子集必脆；② 380px 宽的手机上，**系统中文黑体是厂商针对这块屏幕做过 hinting 的**，比任何按需下载的字体更清晰；
③ 中文的「被设计过」不靠字体，靠**字号、字重、行高、行长、节奏**——这正是 §4 要做的。
**但这不等于不管中文**：v1 最大的发现（中文是页面上唯一没被设计过的部分）在 v2 里由 §4 的排版系统正面解决。

> **实现注意**：`--font-mono` 只挂在**纯拉丁/数字**元素上（如 `<span class="num">2026</span>`），
> 不要让它和中文同处一个文本节点，否则一行里会出现两种完全不同的字宽节奏。

## 4. 移动优先的排版系统

### 4.1 手机段用**固定刻度**，不用 vw

理由：手机可用宽度只集中在 375–430（约 1.15 倍区间），`vw` 流式会让字号随机型抖动，
而当前五个 clamp 已经在手机段完全失效（§1.1）。**固定刻度比假流式更可控。**

```
手机段 320–599px（设计基准 390）—— 固定值
  词标        网络攻防与信息安全    17px / 1.2  / 700  (--font-wordmark)
  主标题                          34px / 1.25 / 700
  区块标题                        24px / 1.3  / 700
  行标题（方向 / 步骤）            20px / 1.4  / 600
  正文                            17px / 1.75 / 400      ← 15.2 → 17
  次级正文                        15px / 1.7  / 400
  小标签                          13px / 1.45 / 500      ← 11 → 13
  输入框 / 下拉 / 文本域           17px / 1.5  / 400      ← 15 → 17（≥16 即不再触发 iOS 缩放）

  底线：正文 ≥17px · 标签 ≥13px · 输入 ≥16px

平板段 600–1023px —— clamp 开始生效
  主标题  34 → 44      区块标题  24 → 28      正文  17 → 18

桌面段 ≥1024px —— 流式
  主标题  44 → 64      区块标题  28 → 34      正文  18 / 1.7
```

### 4.2 行长（中文字/行）

页面左右内边距手机段改为**固定 20px**（≤340px 用 16px），替掉 `6vw`：

| 设备 | 内容宽 | 正文 17px 下的理论行容量 | 判断 |
|---|---|---|---|
| 320（padding 16） | 288px | **16.9 字/行** | 略窄，可接受 |
| 375（padding 20） | 335px | **19.7 字/行** | ✓ |
| 390（padding 20） | 350px | **20.6 字/行** | ✓ 中文舒适区 20–35 |
| 430（padding 20） | 390px | **22.9 字/行** | ✓ |

### 4.3 行高与字重（实测：行高本来就对，字重不对）

- `line-height` 实测 `.tl-desc` 26.6/15.2 = **1.75**、`.notice-body` = **1.8** → **保持不动**。
- 但 `.tagline` 与 `.sec-title` 用的是 `font-weight: 300`，**15.2px 的细体浅灰黑底字**在手机上偏虚。
  正文改 **400**，标题改 **700**——用字重差建立层级，不靠缩小字号。

## 5. 移动优先的结构：8.2 屏 → 约 4.5 屏

`min-height: 100vh` 强制每块占满一屏，是 §1.4（两个空屏）与 §1.5（横屏失控）的共同病根。
**v2 的做法：只有 hero 占满一屏，其余区块按内容高度，不强制 100vh，手机段不做 scroll-snap。**

同时把内容合并：

```
现在（8.2 屏）                      v2（约 4.5 屏）
1. hero            844px            1. hero            约 78svh（内容高度）
2. directions      844px            2. 四个方向          内容高度（4 行 × 88px）
3. timeline        869px            3. 流程 + 公告       合并，内容高度
4. notices         844px ← 空 71%      （公告已并入 3，内容为 1 条时不再独占一屏）
5. apply          1818px            4. 报名表            唯一的长区块（约 2 屏）
6. join            844px            5. 加群 + 友链 + 页脚  合并，内容高度
7. links           844px
```

**手机导航的处置**：删掉 4 个锚点。
理由：① 实测全部 18px 高，且位于第 2–4% 行（单手最难够到的位置）；
② 这是一个线性滚动页，锚点是冗余的。手机头部只保留 **词标 + 阶段状态点（只读）+ `报名` 按钮（44px）**。
**导航变少 = 手机变好**。桌面端保留锚点导航。

### 5.2 横屏与矮屏

`max-height: 500px`（横屏手机）：

- 取消 hero 的 `100svh`，改成内容高度；
- 四个方向从「一行一个」改成**两列**（844px 宽够）；
- 头部缩到 44px；
- **彻底不做 sticky 底栏**（竖屏高度不足时它会吃掉内容）。

### 5.3 顶部进度线

替掉被隐藏的滚动条（`scrollbar-width: none` + `::-webkit-scrollbar{display:none}` 现在让页面**完全没有任何位置反馈**）。
头部底边一条 2px 的 `--signal-line`，宽度反映阅读进度。
**更新时机：只在区块切换时写一次 CSS 变量，不做逐帧更新**（见 §6）。

## 6. 签名元素：信号线，以及零常驻 rAF 的动效预算

### 6.1 用**内联 SVG**，不用 canvas

| | canvas（现状） | 内联 SVG（v2） |
|---|---|---|
| DPR | 需要手动处理（现在 dpr 封顶 2） | 自动 |
| resize | `resize(); seed();` → **地址栏一收一放就重建 150 粒子** | 无需处理 |
| 换色 | 手动拼 rgba 字符串 | `stroke: currentColor`，跟随主题令牌 |
| 常驻开销 | 全屏 1.32Mpx 每帧重绘 | 静态 DOM，无循环 |
| 可访问性 | 需 `aria-hidden` | 可用 `role="img"` + `aria-label`，也可给 `<title>` |

### 6.2 信号线出现在三个地方，每一处都对应真实状态（这是它不变成装饰的规则）

**① Hero — 开机扫过一次（仅此一次的编排）**

```
0ms     网格淡入
200ms   信号线从左到右描出（stroke-dashoffset，900ms）
700ms   词标 + 主标题淡入
900ms   副标 + CTA 淡入
```
`prefers-reduced-motion` 下直接呈现终态。

**② 四个方向 — 每个方向一条自己的波形（签名交互）**

这是本页的记忆点，也是手机上最自然的交互（**点，不是悬停；目标 ≥88px**）：

| 方向 | 波形 | 含义 |
|---|---|---|
| 软件 | 方波 | 离散、确定、0/1 |
| 硬件 | 带噪方波 | 真实世界有抖动、有容差 |
| 算法 | 正弦 | 连续、可解析 |
| 人工智能 | 拟合曲线 + 残差带 | 逼近目标，但永远有误差 |

四条路径**预先生成、静态写在 `<path d>` 里**，切换时做 320ms 的描边过渡。
**切换时不计算、不重绘、不跑循环**——只是换一个 class。

**③ 报名表 — 同一条线变成填写进度读数**

随必填项完成度推进（`stroke-dashoffset` 由 1 → 0）。
只在 `input`/`change` 事件里更新一次，事件用 rAF 合并。这不是装饰——它是**一个真实的完成度读数**。

### 6.3 动效预算

```
--ease-out   cubic-bezier(.16,1,.3,1)     入场
--ease-io    cubic-bezier(.65,0,.35,1)    状态切换
--ease-tap   cubic-bezier(.22,.61,.36,1)  微交互（yui540 那一组）
--d-tap 160ms   --d-morph 320ms   --d-reveal 520ms   --d-sweep 900ms
```

| 层 | 触发 | 实现 | 更新频率 |
|---|---|---|---|
| 开机序列 | 页面加载 | CSS animation，仅一次 | 1 次 |
| 信号线扫描 / 波形切换 | `IntersectionObserver` / 点按 | 预置 path + class 切换 | 按事件 |
| 区块入场 | `IntersectionObserver`（一次性） | 标题 `clip-path` 擦入；列表项 `opacity`+`translateY(3px)`，`--i` 错峰 55ms | 每元素 1 次 |
| 微交互 | hover / 点按 | `scale(1.03)` / 按下 `scale(.99)` | 按事件 |
| 顶部进度线 | 区块切换 | 写一个 CSS 变量 | 每次切段 |

**零常驻 rAF。** 对比现状：一个永久运行的全屏 2D 画布。
**手机上不做逐帧滚动动画**——省电、省热、不掉帧，这比"更炫"重要。

### 6.4 明确删除

| 删除 | 依据 |
|---|---|
| Canvas 雾粒子（约 90 行 JS、150 粒子/帧、53 个 `createRadialGradient`/帧） | 与主题无任何语义关系；`prefers-reduced-motion` 下实测 canvas 像素 `[0,0,0,0]`、`display:none` → **身份归零**。删它是语义决定，不是性能决定（桌面实测 59.9fps、0 掉帧，性能本来够用） |
| `min-height: 100vh`（内容区块） | 实测造成 2 个 71% 空置的屏（§1.4）与横屏 12.2 屏失控（§1.5）；iOS 的 `100vh` 还含地址栏 |
| 手机段 `scroll-snap` | 8.2 屏 + 隐藏滚动条 + 逐屏硬跳 = 零方位感；且长表单与吸附冲突。桌面段保留 `y proximity` |
| `.dir-row .desc { display:none }` | 手机是主要设备，不该删内容 |
| 导航 `mix-blend-mode: difference` | 混色依赖背景亮度；v2 有浅/深两套底色，不可预测 |
| 全局 `.reveal`（`opacity + translateY(24px)`） | 从 `<h1>` 到友链卡同一种入场 = 没有层级 |
| `.dir-row` 上 `transition: padding-left` | 布局属性参与过渡，每帧触发布局 |

## 8. 明确不做

| 不做 | 为什么 |
|---|---|
| 平滑滚动库（Lenis 等） | 原生滚动可键盘、可触控、可 `Home/End`。手机上劫持滚动是明确的负收益 |
| 任何按文案冻结的中文字体子集 | 文案是自动生成的，子集必脆（§0） |
| 背景视频 / 大图 | 站点现在零图片。**保持零图片** |
| WebGL / 3D | 原设计已明确放弃 |
| 自定义光标 / 光标跟随 | 与内容无关，且手机上不存在 |
| Loading 遮罩 | 一个招新页不值得让同学等 |
| 每个区块都做动效 | 除信号线外全部静默入场。**动作只花在两处**（hero 开机 + 方向波形） |
| 逐帧滚动动画 | 手机上耗电、发热、掉帧（§6.3） |
| 大数字 stat card / 渐变强调 / `01 02 03` 序号 | 通用模板特征。方向列表的四个方向不是序列 |
| 深色模式**另做一套设计** | 深色只是同一套令牌的取值替换（§3.3），不是第二个设计 |

## 11. 风险与回退

| 风险 | 影响 | 缓解 |
|---|---|---|
| 浅色底是相对现状（纯黑）的**大改** | 用户可能更喜欢现有的深色 | ① 深色模式一并实现（同一套令牌，`prefers-color-scheme`）；② 令牌集中在 `:root`，**一次替换即可整体翻转**。**这是最需要你先拍板的一项** |
| wordmark 子集字形掉落 | 只有当「实验室名」本身被改写时才会发生 | 实验室名是固定词标；`--font-wordmark` 栈里紧跟 `Songti SC` / `Source Han Serif` 系统宋体兜底；重建方法写在 `index.html` 注释里 |
| 固定刻度在大屏手机上偏小 | 430px 上正文 17px 只到 22.9 字/行 | 430px 已经是舒适区上限；如觉偏小，430–599 段可整体 +1px，是单点改动 |
| 粘性底栏遮挡内容 | 手机端最后几个字段被挡 | 底栏只在 `#apply` 进入视口时出现；表单底部留 `padding-bottom` = 底栏高度 + 安全区 |
| 方格背景在低端机上重绘 | 大面积 `repeating-linear-gradient` 滚动重绘 | 网格画在 `position: fixed` 的伪元素上，不参与滚动重绘；`will-change` 不常驻 |
| 波形切换被误读为"加载动画" | 语义传达失败 | 每条波形配 13px 说明文字；`aria-label` 写明方向名 |
| 手机端删掉锚点导航后有人想跳段 | 少数人需要 | 头部保留 `报名`；同时顶部进度线提供位置感。如需要可加一个 44px 的「目录」按钮开底部弹层（**列为可选项，默认不做**） |

## 12. 自检：离「默认样貌」多远

| 默认样貌 | v2 | 判断 |
|---|---|---|
| ① 暖奶油底 `#F4F1EA` + 高对比衬线 + 赤陶色 | 纸面 `#f7f7f4`（冷中性，与奶油对比 1.051）、强调色蓝 `#17469e`、中文不上衬线 | **避开**。参考站 anthropic 用的正是这一套——只学它的结构（sticky + 滚动变量），不学配色 |
| ② 近黑底 + 单一酸绿/朱红 | 默认浅色纸面；强调色是有语义锁定的蓝墨（只表示"正在被绘制"） | **避开** |
| ③ 大报式：发丝线 + 零圆角 + 密集分栏 | 有发丝线，但结构是**内容高度的纵向节拍**，不是分栏报纸 | **部分接近但动机不同**：线是节拍与网格对齐，不是分栏边界 |
| 通用模板：大数字 + 小标签 + 渐变强调 | 无渐变、无 stat card、无 hero 大数字 | **避开** |
| 通用模板：`01 02 03` 序号 | 流程用**后端真实状态机 token**（`warmup/signup/review/result`，`lib/phase.js` 已有，HTML 里已有 `data-phase`） | **避开** |

**相对 v1 改变的决策**：

1. 电路板 → **方格纸 + 信号线**。电路板偏心硬件；方格纸是四个方向共同的草稿纸。
2. 冻结 37 个中文标题字 → **只冻结实验室名 9 个字（2.7 KB）**。文案会变，词标不会。
3. 滚动驱动的全站 spine → **零常驻 rAF**。手机是主设备，常驻循环就是成本。
4. 五个 clamp 微调 → **手机段改固定刻度**。实测证明 clamp 在手机段是常数，与其修不如换。
5. 每块 `min-height: 100vh` → **只有 hero 满屏**。实测 2 个屏空置 71%、横屏 12.2 屏失控，病根就在这一条。
6. 保留桌面锚点导航，**删掉手机锚点导航**。18px 且在最高区，且线性页里冗余。
7. 行高**不动**（实测本来就对：1.75 / 1.8），改的是字号与字重。
