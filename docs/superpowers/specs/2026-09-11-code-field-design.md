# 代码场域（Code Field）设计计划 v3

> 取代 v2「方格纸 / PLOTTED」。v2 的方格子、波形框、顶部标签栏全部作废。
> 本版的核心更正：**代码是场域，不是组件。**

---

## 0. v2 为什么不过关

诊断到 4 条，都是我理解错了：

| # | v2 做了什么 | 错在哪 |
|---|---|---|
| 1 | 在 hero 里放了一个「代码组件」（差异面板） | 你要的是**代码当背景**，不是页面上多一个代码块。我把语义当成了装饰题材。 |
| 2 | 差异面板只有 2 行假代码，一行之差 | 「一行之差」这个论点太薄，撑不起「四个方向」这么大的一件事。而且假代码看不出是**什么语言**。 |
| 3 | 四种记法（C/伪码/渐近/ML）算作「四个方向的区别」 | 你要的是**真实语言的真实写法**：软件=Spring Boot，硬件=C，算法=Python，AI=终端 harness。 |
| 4 | 深色是可选主题，浅色是默认 | VSCode 的**识别色就是深色**。默认必须是深色，浅色只是礼让系统偏好。 |

还有一条方法论上的错：我用「浅灰发丝线 + 等宽字」去暗示代码，而不是**真的把代码放出来**。代码的辨识度来自**语法颜色**，不是等宽字。等宽字只是必要条件。

## 1. 命题：代码是场域

**页面 = 一个开着代码的编辑器。内容 = 浮在编辑器上的一块块面板。**

三句话讲清全部结构：

1. 有一层**全屏的代码**在动。它逐字打字，打的是**真代码**，带**真语法高亮**。
2. 内容（标题、方向、流程、报名表）是**不透明的编辑器面板**，盖在代码上。
3. 面板**盖不到的地方**（桌面端左侧的空白、手机端面板之间的间隙），你看到的是**未被压暗的、全饱和的原生代码**。

第 3 条是这套设计成立的关键，也是它区别于「背景图 + 内容」的地方。

### 为什么不能靠「压暗背景」实现

我把 VSCode Dark+ 的 token 色按 alpha 叠在编辑器底色上算了一遍：

```
token                     1.0      0.8      0.6      0.5      0.4      0.3
comment #6A9955         4.95     3.68!    2.64.    2.23.    1.88.    1.59.
keyword #569CD6         5.59     4.07!    2.88.    2.40.    1.98.    1.64.
string  #CE9178         6.24     4.48!    3.11!    2.57.    2.12.    1.72.
type    #4EC9B0         8.09     5.65     3.77!    3.03!    2.41.    1.90.
function #DCDCAA       11.66     7.90     5.04     3.97!    3.03!    2.28.
variable #9CDCFE       11.05     7.52     4.82     3.81!    2.92.    2.21.
number  #B5CEA8         9.70     6.69     4.37!    3.44!    2.70.    2.09.
control #C586C0         5.92     4.28!    3.02!    2.48.    2.04.    1.69.

标记：无 = ≥4.5:1 可读    ! = 3~4.5:1 可辨形    . = <3:1 糊成灰

alpha=1.0  →  8/8 个 token ≥4.5:1
alpha=0.8  →  4/8
alpha=0.5  →  0/8   ← 到这里语法颜色全没了，代码退化成灰噪声
```

**结论：不能压暗。** 压到 0.5 就只剩灰点，看起来像假代码——正好是 v2 的毛病。所以代码层保持 **alpha 1.0 全饱和**，靠**面板遮挡 + 版面留白**来控制它，不靠透明度。

好处是：露出来的代码是真的可读的。它会成为版面上真正有信息量的部分，而不是纹理。

## 2. 四个「文件」——真实内容

四段都是**网络攻防语境下的真代码**，不是通用示例。语言、缩进、命名习惯都对得上，程序员扫一眼就知道是什么。

### 2.1 软件 → Spring Boot / Java

```java
@RestController
@RequestMapping("/api/auth")
public class AuthController {

    private final TokenService tokens;
    private final UserRepository users;

    // 密码比对交给 PasswordEncoder，不要自己写 ==
    @PostMapping("/login")
    public ResponseEntity<Token> login(@Valid @RequestBody LoginRequest req) {
        return users.findByStudentId(req.studentId())
            .filter(u -> encoder.matches(req.password(), u.hash()))
            .map(tokens::issue)
            .map(ResponseEntity::ok)
            .orElseGet(() -> ResponseEntity.status(401).build());
    }
}
```
*辨识点：注解（黄）、关键字（蓝）、类型（青）、Optional 链式 + 方法引用。*

### 2.2 硬件 → C

```c
#include <stdint.h>
#include <string.h>

#define PERIPH_BASE 0x40000000u
#define FLASH_SR    (PERIPH_BASE + 0x10u)
#define REG(off)    (*(volatile uint32_t *)(off))

/* 长度是外面传进来的，先夹住再搬 */
int fw_load(uint8_t *dst, const uint8_t *src, size_t len, size_t cap)
{
    if (len == 0u || len > cap) {
        return -EINVAL;
    }
    for (size_t i = 0; i < len; i += 4u) {
        while (REG(FLASH_SR) & FLASH_BSY) {
            __NOP();
        }
        memcpy(dst + i, src + i, 4u);
    }
    return 0;
}
```
*辨识点：`#define` 宏、`volatile` 寄存器、`0x…u` 字面量、`__NOP()`、`size_t`。*

### 2.3 算法 → Python

```python
from hashlib import sha256
from secrets import token_bytes

# 生日界：n 位摘要大约 2^(n/2) 次就会撞上。
# SHA-1 是 160 位，所以真实强度只有 80 位 —— 这就是它被淘汰的原因。
def collision_bound(bits: int) -> int:
    return 1 << (bits // 2)

def find_collision(bits: int, limit: int = 1 << 24) -> tuple[int, int] | None:
    seen: dict[bytes, int] = {}
    bound = min(limit, collision_bound(bits) * 2)
    for i in range(bound):
        digest = sha256(i.to_bytes(8, "big")).digest()[: bits // 8]
        if digest in seen:
            return seen[digest], i
        seen[digest] = i
    return None
```
*辨识点：`def`（蓝）、类型注解、`#` 注释（绿）、位运算、返回值注解。*

### 2.5 字形安全（实测）

这些字形我在这台机器的等宽栈下**逐个渲染测过像素**，全部有覆盖。但 iOS/Mac/Windows 的等宽字体覆盖不同，`⏺ ⎿ ⏵` 都在 U+23xx 区，是**风险区**：

```
✓ U+23FA ⏺   ✓ U+23BF ⎿   ✓ U+23F5 ⏵   ✓ U+273B ✻      ← 有覆盖，但属风险区
✓ U+2500-257F ─│┌┐└┘├┤╭╮╰╯   ✓ U+2580-259F █▁░▒       ← 几乎每个等宽字体都有
```

对策：终端档的字体栈在等宽字体之后**追加符号字体**：

```
ui-monospace, "SF Mono", Menlo, Consolas, "DejaVu Sans Mono",
"Segoe UI Symbol", "Apple Symbols", monospace
```

并且只在这三个字形上依赖它（`⏺ ⎿ ⏵`）。**前景文字一律不用风险区字形**——背景层是 `aria-hidden` 的装饰，缺字只是难看；前景缺字就是信息丢失。`━`（U+2501，pip 进度条用）属安全区，可以放心用。

## 3. 四种运动，各有语义

这是本版最需要你过目的部分。**动效不是「让它动起来」，是四种不同的运动各自对应四件真实的事。**

### 3.1 打字（编辑器档）—— 逐字 + 真错字回删

| 行为 | 参数 | 为什么 |
|---|---|---|
| 逐字输出 | 基础 38ms/字，抖动 ±22ms | 匀速打字是机器；人手有节奏波动 |
| **行首缩进瞬间出现** | 0ms | 编辑器自动缩进，人不会一个格一个格敲空格。**这个细节最像真人** |
| 标点后停顿 | `;` `{` `}` `,` 后 180–320ms | 换行的思考停顿 |
| **错字 → 回删 → 重打** | 约每 120 字一次 | 就是你要的「撤回效果」。打错一个字符，停 220–400ms，退格，再打对 |
| 光标 | 1px 竖条，VSCode `#AEAFAD`，530ms 方波闪烁 | 编辑器光标是竖条不是方块 |

打字速度 38ms/字 → 一个 14 行的片段约 **13–15 秒**打完。

### 3.2 切档 —— 整片回删

换方向时，先把当前文件**从末尾逐字删掉**（比打字快 3 倍：约 12ms/字，带连退），删空后进入过渡。

**顺序不能反**：真实开发是「关掉这个项目 → 装依赖 → 打开新文件」。所以是 **回删 → 依赖拉取 → 新文件打字**。

### 3.3 过渡 —— 依赖拉取（滚动）

### 3.4 终端档 —— 流式输出，不是打字

**AI 档的运动必须和编辑器档不一样**，否则四档运动变成一种运动，场域就不成立了：

| 编辑器档 | 终端档 |
|---|---|
| 逐字打字，慢，有错字 | **整块跳出来**，一块一块追加 |
| 光标在代码里 | 光标在提示符后 |
| 打字是主角 | **停顿才是主角**（等工具返回） |

终端档的节奏：`> 提示符 + 用户提问逐字打`（这个是人打的，打）→ 停 400ms → `⏺ Read(...)` 整块出现 → 停 700ms → `⎿ Read 128 lines` 整块出现 → 停 500ms → 助手分析整段出现（可逐字，模拟流式）→ 停 1.2s → `⏺ Update(...)` → diff 两行依次出现 → 停 800ms。总约 **14–18 秒**。

额外细节：`✻ Cogitating…` 前面加一个 **8 帧旋转指示器**（`✻ ✳ ✢ ✽` 轮转），这是 TUI 的真实行为。

## 4. 底色与配色：VSCode Dark Modern 原生值 + 3 处修正

### 4.1 好消息：token 色全部达标

VSCode Dark+ 的 8 个 token 色压在 `#1F1F1F` 上，**全部 ≥4.5:1**：

```
keyword   #569CD6   5.59 ✓      string    #CE9178   6.24 ✓
control   #C586C0   5.92 ✓      number    #B5CEA8   9.70 ✓
type      #4EC9B0   8.09 ✓      comment   #6A9955   4.95 ✓
function  #DCDCAA  11.66 ✓      variable  #9CDCFE  11.05 ✓
```

**所以语法高亮可以原样照用，不用为了对比度改色。** 上一版我为了达标自己调过色，这次不用——这是「原生 VSCode」能成立的技术前提。

### 4.2 需要修正的 3 处（VSCode 自己有两个值不达标）

| 用途 | VSCode 原生 | 实测 | 修正为 | 修正后 |
|---|---|---|---|---|
| 行号 | `#6E7681` | **3.59 ❌** | `#8A9199` | 5.17 ✓ |
| 焦点环（压深底） | `#0078D4` | **3.64 ❌** | `#4DA3E8` | 6.06 ✓ |
| disabled | `#6E7681` | **3.59 ❌** | `#8A9199` | 5.17 ✓ |

**但有一处要注意，别改错方向**：

```
#0078D4 压深底        → 3.64 ❌（不能当边框/焦点环）
#0078D4 + 白字        → 4.53 ✓（可以当填充按钮、状态栏）
#4DA3E8 + 白字        → 2.72 ❌（不能当填充背景）
#4DA3E8 压深底        → 6.06 ✓（可以当边框/焦点环/深底上的链接）
```

所以两个蓝**分工不同，不能互相替代**：`#0078D4` 是**填充面**，`#4DA3E8` 是**描边/深底文字**。

**方向色直接用四个 token 色**——这是「四个方向」在配色上唯一需要的机制，概念上和语法高亮同源：**换方向 = 换一种记号色**，像编辑器打开另一种文件类型。

### 4.4 默认深色

- **默认深色**，不等系统偏好——VSCode 的识别色就是深色，这是身份。
- 系统偏好浅色时，切到 `VSCode Light+` 令牌（保留，一份令牌文件的事）。
- 理由：直接在系统浅色模式下硬上深色是**违背用户偏好**的；礼让系统偏好 + 深色作默认，两件事不冲突。
- **如果你要「永远深色」**，那是一行的事（见 §11 决策点 A）。

## 5. 构图：三层，以及内容面板为什么必须不透明

```
z 2  .shell 内容面板        background: var(--ed-panel)  不透明
z 1  .rail  行号 + 左边缘   只在桌面端，窄栏
z 0  .codefield  全屏代码    alpha 1.0 全饱和 token 色
```

**内容面板必须不透明**，因为：
- 代码全饱和 → 半透明面板上的文字会和代码打架，对比度不可控
- `backdrop-filter: blur()` 在手机上很贵（低端安卓滚动掉帧），不能用

于是「代码是背景」靠**遮挡关系**表达，不靠透明度。面板是「挖出来的一块」，代码是「那面墙」。

## 6. 页面骨架

| 区块 | 内容 | 代码场域状态 |
|---|---|---|
| **hero** | 实验室名 / 一句话 / 四个方向词 / 报名 CTA | **全运动**：打字 + 错字回删 |
| **directions** | 四行。每行：方向名、语言、一句话、招什么 | 滚到此时切档；点/悬停某行 → 立刻切到该档 |
| **flow** | 报名 → 笔试 → 面试 → 进组 | 切档频率降低 |
| **intro** | 实验室介绍 | 静止 |
| **apply** | 报名表（全部现有功能保留） | **静止**（显示一个完整文件） |
| **join** | 加群二维码 | 静止 |
| **底部状态栏** | VSCode 蓝 `#0078D4` + 白字：阶段 · 当前方向 · 必填进度 · 加群 | — |

### 底部状态栏取代顶部标签栏

v2 的顶部标签栏是「加了一个代码组件」的典型。**VSCode 的状态栏在底部**，而且是蓝底白字——`#0078D4` + 白字 = **4.53:1 ✓** 达标。

而且它**真的有用**：手机上拇指最容易够到，承载「阶段」「必填进度」「加群」三个真实状态。这不是装饰，是把状态放在最该放的地方。

### flow 用 git log

流程天然就是提交历史。四个阶段做成四条 commit：`○ 报名开放` / `○ 笔试` / `○ 面试` / `○ 进组`，带简短的 meta 行。比时间线组件更贴题。

## 7. 运动预算：按内容密度递减

**常驻满速动画是这一版最大的风险**——费电、分神，而且盯着看 1 分钟就烦。规则：

| 区域 | 运动 |
|---|---|
| hero / directions | 全速：打字、错字回删、切档、依赖过渡 |
| flow | 减速：只在滚到该区时打一小段，之后停住 |
| apply / join | **完全静止**：显示一个完整文件，光标闪，不切档 |

核心一句：**动效是主体时全速，动效是壁纸时静止。** 填表的时候背景还在打字，是纯粹的干扰和浪费。

实现：用 `IntersectionObserver` 观察「运动权」区域，滚出就 `stop()`。填表期间**完全不跑定时器**。

## 8. 性能与降级

打字本身很便宜——**真人打字本来就是 8–12 字/秒**，所以上限天然很低，不需要 rAF 满帧。但全屏图层每次改动都要重绘，所以要立规矩：

- `.codefield` 提升为独立合成层（`transform: translateZ(0)` / `will-change: transform`），**切断它对整页重绘的影响**
- 每次更新只改**一个文本节点的 textContent** → 只重排一行
- `contain: strict` 限制布局影响范围
- **不跑 rAF 循环**：用 `setTimeout` 按字节奏调度（38ms 量级），空闲时零回调
- `document.hidden` → 立即停
- `prefers-reduced-motion: reduce` → 不打字、不切档、不过渡；**直接显示完整文件**
- 实测门槛：CDP 4× CPU 降速下，滚动帧时间不劣化于无该图层时的 1.5×

## 11. 待你定的三个点

**A. 深色是否封死**
现在是「默认深色 + 系统浅色时切浅色」。要「永远深色」的话是一行的事。我建议保留浅色——白天户外手机看得清，而且不用违背系统偏好。

**B. 四档内容是否对**
§2 那四段代码是我按「网络攻防语境」写的。**这是最需要你确认的地方**——如果你想让软件档写更偏 Web 漏洞、算法档写密码学而不是哈希碰撞、或者 AI 档换成别的场景，现在改成本最低（只有一个数据文件）。

**C. 编码档要不要真的可读**
现在代码行是**真的代码**，人可以停下读。另一种做法是让它更像纯纹理（但 §1 算过，压暗就变灰噪声）。我倾向前者。

## 14. 第二轮修订（素材长度 / 非匀速 / 思考停顿 / 全局背景）

计划里没有预见到的三件事，都是实测抳出来的：

| 计划里没写 | 问题 | 解决 |
|---|---|---|
| 素材长度没有下限 | 14–22 行代码 + 8 行依赖日志，看起来不像真的在装东西 | 代码 → **46–55 行**；日志 → **22–26 行**，pip 加 4 条会自己填的进度条 |
| §3.1 只写了「抖动 ±22ms」 | 抖动不够 —— 实测击键间隔几乎是常数（p50/p90 = 1.05×），一眼就是机器 | 改成**连击模型**：敲一串 5–15 字 → 停 140–470ms（偏斜分布）+ 3.5% 走神。实测 **p50/p90 = 11.6×** |
| §3.1 只写了「约每 120 字一次错字」 | 太稀（整个文件只 1–2 次），而且错了看不出来 | 提到 **1/60 字**（≈1.7%，接近真人），分单字错 / 整词错两种，错的字挂 **VSCode 同款红色波浪下划线** |
| §3.4 只写了「停顿是主角」 | 没具体说停多长时间、怎么表现 | 加 `think`（转圈 + 秒数 + token 数递增，四档共 ≈23s）与 `stream`（正文按 chunk 追加）两种新运动 |
| §10 验收标准没写整轮时长 | — | 实测 **104s/档，整轮 ≈7 分钟**（上一版 17.7s/档） |

- [ ] 错字钩子：`CODEFIELD_TYPO_P = 0` 则**零**错字，`= 1` 则**必定**错（回归可断言）
- [ ] 击键间隔 p90/p50 **> 5×**（低于这个值就是匀速）
- [ ] **HTML 里零个 `style` 属性**（被 CSP 的 `style-src-attr` 拦，会静默失效）
- [ ] 素材加长后行宽预算仍然 ≤ 40 宽度单位（中文算 2）

## 15. 第三轮修订（整行重写 / 明确的暂停 / 代码带只占上侧）

这一轮推翻了计划里两个已经写定的决定：

| 计划里写的 | 实测/反馈的问题 | 改成 |
|---|---|---|
| §5 「代码层 `position: fixed` `inset: 0` 贯穿全页」 | 全屏铺满看着像一个铺到底的组件，而且每一屏都在动很吵 | **页面上侧一条带子**，`absolute` + `clamp(240px,40vh,380px)`，底部 `mask-image` 渐隐到纯黑。实测占整页 **13–18%** |
| §7 「离开视口暂停」用 `data-motion` 观察**内容区块** | 滚回顶部会**重新开始**（因为恢复=重新 `switchTo`），不是接着演 | 暂停**不取消定时器**，原地等；观察**代码带自己**；增加「焦点进表单就暂停」 |
| §3.1 只有「打错一个字符」 | — | 新增**整行重写**：全选删掉重打成另一个版本，见 §3.6 |

新增的硬约束：

- [ ] `--cf-h` / `--cf-fade` **必须定义在 `:root`** —— 写在 `.cf` 上时兄弟元素 `.hero` 读不到，会静默取兜底值
- [ ] 底边 36% 留给渐隐区：活动行不得落入渐隐（否则最新内容最不清）
- [ ] 终端/日志**不得用 `justify-content:flex-end`**（那是「从下往上」的根因）
- [ ] `rev` 的键必须是原文，且必须能被运行时匹配上（不匹配就永远不触发）
- [ ] 暂停/API 的状态获取器必须用 `Object.defineProperty`，不能写进 `Object.assign`

```
hold: 700–2100ms   打完停这么久才决定改（比打错的 360–900ms 更长）
```

## 16. 第四轮修订（玻璃质感 / 背景不推版面）

这一轮把 §5 的版面决定又推翻了一次。核心认知：
**代码带不能占版面，它是内容滑过去的一面墙。**

| 计划/上轮写的 | 问题 | 改成 |
|---|---|---|
| §15 `.cf { position: absolute }` | 带子跟着页面滚走，只有第一屏能看到代码 | 改回 `fixed`：钉在页面上侧，**每张卡片滑过时背后都经过活的代码** |
| §15 `.hero { padding-top: calc(var(--cf-h) - 56px) }` | 版面给背景让高度 → 卡片被推下去 | `.hero { padding: 18px 14px 0 }`，实测卡片顶 ≤ 26px |
| §5 「内容面板必须**不透明**」 | 用户要求玻璃质感 | 改成玻璃，但需要三条硬约束，见下 |

### 玻璃的三条硬约束（都是采像素量出来的）

- [ ] **底色不能是纯黑**。深 tint 压纯黑 = 卡片和背景同一个黑，只剩描边可见
- [ ] **backdrop-filter 必须压暗（`brightness(.85)`），不能提亮**。
      提亮会放大背后的代码，实测把文字对比度打到 2.09:1
- [ ] **文字对「背后最亮像素」≥ 4.5:1**。实测值：
      主文字 `#e8e8e8` 11:1、弱文字 `#b6bdc7` 7:1、标签 6.3–9.5:1
- [ ] **模糊半径是透明度的杠杆，不是 tint**：模糊越大→亮峰摊得越平→同样的可读性下 tint 可以更低。
      实测 `blur 20/tint .62`（38% 不透明，chP99=36）→ `blur 34/tint .22`（**78% 不透明**，chP99=66）：
      更透明、颜色透进来更清楚、对比度还从 5.45 升到 6.66
- [ ] **弱文字有硬下限**：卡片越透，次级文字这个层级越窄。踩过两次：
      `#8b93a0` → 4.28:1、`#a2aab6` → 5.05:1，最终定为 `#b0b8c4`（≥5.9）
- [ ] **小控件不能和卡片共用一套玻璃参数**：暂停徽标浮在代码带最亮的那一段上，
      而且里面没有留白缓冲，必须 `tint .90 + brightness(.7)` 才到得了 4.5:1

### 测量方法的两个坑（都踩过）

1. 测「透过玻璃能看到什么」时，探针要**去掉玻璃自己的装饰**（边框/高光/反光），
   且采样区内缩 —— 否则量到的是玻璃自己的顶边高光（曾得出「2.09:1」的假结论）
2. 藏掉文字来量背后的底时，只能藏**文字本身**，不能藏容器 ——
   `visibility: hidden` 会把元素自己的背景也藏掉（曾在徽标上量出假阳性的 3.23:1）

**共同点：探针不能把要测的东西自己也藏掉、或算进去。**

弱文字原定的 `#8b93a0` 在玻璃顶边高光那一带只有 4.28:1，所以弱文字整体提到
`#a2aab6` / `#b4bcc6`。**玻璃会让「次级文字」这个层级变得很窄** —— 弱文字必须有下限。

### 测量的教训（值得记住的方法论错误）

第一版「最坏情况对比度」测出 2.09:1，扫 18 组参数**结论完全不变**。
这本身就是信号：如果调参没影响，说明测的不是那个东西。
定位最亮像素的坐标后发现是**玻璃自己的顶边高光**（x=1,y=0）。

→ 测「透过玻璃能看到什么」时，探针必须去掉玻璃自己的装饰（边框/高光/反光），
且采样区要向内缩，避开边缘那 1px。
